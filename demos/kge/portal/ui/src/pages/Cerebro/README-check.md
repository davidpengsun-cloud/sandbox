# The `useStream` check (B1a)

The check [cerebro.md §4.3](../../../../../../../docs/use-cases/kge/platform/cerebro.md#43-the-bff-endpoint) and decision D2 call for, run 2026-11-15 as the first job of the Cerebro pull request.

## Result

**Option B passes at the hook level. Option A is not taken.**

| Option | What the portal's server does | Result |
|---|---|---|
| A | Answers the LangGraph API calls the hook makes (`/info`, threads, runs) | Not taken. On this path the hook creates a thread (`POST /threads`), streams a run on it (`POST /threads/{id}/runs/stream`) and reads its history back (`/threads/{id}/history`). The server would have to keep threads between requests, which §4.3 rules out (the server keeps no state) |
| B | Serves the hook's custom-backend adapter (`FetchStreamTransport`) | Passes. The adapter POSTs `{ input, command, config, context }` to one URL and reads LangGraph's server-sent events back. At the check the page sent the conversation as `input.messages` on every request, and on a resume `command.resume` with it, so the server ran each turn from the request alone; since #625 the server keeps the conversation by the hook's thread id (below) |

Pass condition, as §4.3 states it: an answer streams, a tool call shows, and the stream pauses and resumes on the person's answer, against the portal's server, with no LangGraph server running. The check was run with a Confirm; since #624 the only pause is a question back to the person (the HITL card), and the test resumes it with the person's pick.

| Part of the condition | Evidence |
|---|---|
| Streams an answer | `streamCheck.test.js`: the pinned hook, on the adapter, against the portal server's own handler (`server/src/cerebro/route.js`, called in process) |
| Shows a tool call | The same test: the `ask` tool call reaches `stream.messages` |
| Pauses and resumes on the person's answer | The same test: `__interrupt__` (kind `hitl`) reaches `stream.interrupt`. The pick sends `command.resume` (`{ pick }`) alone, on the same thread id, and the answer arrives |
| Server holds nothing between calls | Held at the check; since #625 the server keeps each conversation (below), and a resume carries no message |
| No LangGraph server | Neither test starts one. The handler imports nothing |

What the later jobs added on top of the check:

- B1b copied Agent Chat UI's chat view, conversation list and inbox into `components/agentchat/` and runs them on this stream. The hook's own resume (`resumeSubmit`) sends `input: null` with `command.resume`, which the route refuses since the server holds no conversation; the copied inbox calls `submit({ messages }, { command: { resume } })` with the conversation the page holds instead.
- B5a-i put the agent behind the route (`server/src/cerebro/agent.js`, a LangGraph.js graph on a LangChain model) and mounted it at `POST /api/cerebro/stream` behind the portal's sign-in and a Cerebro role (`server/src/cerebro/chat.js`). Parts stream as `messages` events carrying `[part, metadata]`, since the hook merges parts only from events of that name. A pause sends the state as `values` first, then the same state with `__interrupt__`. LangChain's and LangSmith's telemetry is switched off in the process, the kit and Terraform (`server/src/cerebro/telemetry-off.js`).
- Then: KGE's MCP tools (B5a-ii).

## Pins

Pinned exactly, with lock files regenerated by npm 10.9.10 (`npx npm@10 install --save-exact`), the version in the portal image:

| Package | Version | Where |
|---|---:|---|

The hook's adapter interface is still changing between releases (D2), so a bump of `@langchain/langgraph-sdk` reruns `streamCheck.test.js` before it lands.
- B5a-ii gave the agent KGE's MCP tools as the person (`server/src/cerebro/tools.js`): a bearer from KGE's `POST /session/bearer` once per turn, in `x-kge-authorization`, never sent to the page. It also paused an AI-Generated answer for a Confirm; #624 removed that pause (owner, 2026-11-21): answers are delivered with their label, never held.
- #624 made every question back to the person one pause, a `choose` tool call the portal answers itself (never sent to KGE): a clarification's choices, or the agent's own question. Its interrupt (`kind: "hitl"`) carries the question and its options, and the page shows it on the HITL card (`chat/HitlCard.js`). The resume request carries the conversation up to the unanswered `choose` call, with `{ pick }` or `{ other }`; the offer to compare the figures after a difference answer is a `choose` call with no pause, answered with `{ pick }` or `{ month }` the same way.
- #625 moved the conversation to the server: the portal keeps each person's conversations by the hook's thread id (`config.configurable.thread_id`, a UUID the page makes for a new chat). A question sends the one new message as `input.messages`, a resume sends `command.resume` with `input: null`, and Edit or Try again on an earlier question names it as `context.rewind`. The page lists, opens and deletes conversations through `/api/cerebro/conversations` (`chat/chatSession.js`); `streamCheck.test.js` checks the hook on the new route, and the page's own tests run on a stand-in for these routes (`chat/chatTestServer.js`).
