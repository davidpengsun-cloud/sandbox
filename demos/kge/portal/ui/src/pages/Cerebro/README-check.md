# The `useStream` check (B1a)

The check [cerebro.md §4.3](../../../../../../../docs/use-cases/kge/platform/cerebro.md#43-the-bff-endpoint) and decision D2 call for, run 2026-11-15 as the first job of the Cerebro pull request.

## Result

**Option B passes at the hook level. Option A is not taken.**

| Option | What the portal's server does | Result |
|---|---|---|
| A | Answers the LangGraph API calls the hook makes (`/info`, threads, runs) | Not taken. On this path the hook creates a thread (`POST /threads`), streams a run on it (`POST /threads/{id}/runs/stream`) and reads its history back (`/threads/{id}/history`). The server would have to keep threads between requests, which §4.3 rules out (the server keeps no state) |
| B | Serves the hook's custom-backend adapter (`FetchStreamTransport`) | Passes. The adapter POSTs `{ input, command, config, context }` to one URL and reads LangGraph's server-sent events back. The page sends the conversation as `input.messages` on every request, and on a resume sends `command.resume` with it, so the server runs each turn from the request alone |

Pass condition, as §4.3 states it: an answer streams, a tool call shows, and the stream pauses and resumes on Confirm, against the portal's server, with no LangGraph server running.

| Part of the condition | Evidence |
|---|---|
| Streams an answer | `streamCheck.test.js`: the pinned hook, on the adapter, against the portal server's own handler (`server/src/cerebro/route.js`, called in process) |
| Shows a tool call | The same test: the `ask` tool call reaches `stream.messages` |
| Pauses and resumes on Confirm | The same test: `__interrupt__` reaches `stream.interrupt`. Confirm sends the conversation with `command.resume`, and the answer arrives |
| Server holds nothing between calls | `server/test/cerebro-stream.test.js`: a resume runs only from what its request carries |
| No LangGraph server | Neither test starts one. The handler imports nothing |

What the later jobs added on top of the check:

- B1b copied Agent Chat UI's chat view, conversation list and inbox into `components/agentchat/` and runs them on this stream. The hook's own resume (`resumeSubmit`) sends `input: null` with `command.resume`, which the route refuses since the server holds no conversation; the copied inbox calls `submit({ messages }, { command: { resume } })` with the conversation the page holds instead.
- B5a-i put the agent behind the route (`server/src/cerebro/agent.js`, a LangGraph.js graph on a LangChain model) and mounted it at `POST /api/cerebro/stream` behind the portal's sign-in and a Cerebro role (`server/src/cerebro/chat.js`). Parts stream as `messages` events carrying `[part, metadata]`, since the hook merges parts only from events of that name. A pause sends the state as `values` first, then the same state with `__interrupt__`. LangChain's and LangSmith's telemetry is switched off in the process, the kit and Terraform (`server/src/cerebro/telemetry-off.js`).
- Still to come: KGE's MCP tools and the `confirm_first` pause (B5a-ii).

- B5a-ii gave the agent KGE's MCP tools as the person (`server/src/cerebro/tools.js`): a bearer from KGE's `POST /session/bearer` once per turn, in `x-kge-authorization`, never sent to the page. An `ask` reply with `confirm_first` pauses on a checkpointer made for the turn; the interrupt carries the figure-free question and the label alone. The resume request carries the conversation again; the turn replays the pending `ask` call without the model and resumes at the pause with the person's Confirm or Decline.
