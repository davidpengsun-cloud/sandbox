# Telemetry and model posture, kit 0.14.73

The KGE image's effective defaults, read from the image itself as this kit was built, with no setting given. Generated by the kit's build, never written by hand. A deployment changes a default only by setting it; the test drive's report, under Telemetry and model posture, gives the same values as an installed job reads them. Each value names the tests that prove it.

## Client-info headers

Google's client libraries name themselves, their versions and the runtime on the calls they make: the x-goog-api-client header, and a User-Agent naming each library.

- The portal: its calls to Google APIs (BigQuery, Vertex AI, Cloud Trace and their token requests) carry no x-goog-api-client or other x-goog-*-client header, and the portal's own User-Agent, kge-portal; what authentication needs (authorization, x-goog-user-project, Metadata-Flavor) still passes.
- KGE: KGE's Python Google clients still send Google's client-info header (x-goog-api-client) to Google APIs; tracked for a later kit. Claude on Vertex AI is called with KGE's own User-Agent and none of the Anthropic SDK's X-Stainless-* headers.
- Cloud Trace: KGE's and the portal's trace exporters, where TRACING=cloudtrace, send OpenTelemetry's own User-Agent (OTel-OTLP-Exporter, its language and version).
